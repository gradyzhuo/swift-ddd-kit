1.0.0 “Ambient Context & Pluggable Metadata” BREAKING

狀態:branch feature/ambient-context-pluggable-metadata · PR #6

1.0 把 event metadata 從固定的 external: [String:String]? 字串字典通道， 全面改成型別安全的 ambient context 機制。Domain 層 （AggregateRoot / DomainEvent / Usecase）完全不受影響。

🚀 新增

  • EventMetadata — 新的 marker protocol（Codable & Sendable， 不規範任何欄位）。應用層自訂 metadata schema 時 conform 它。
  • EventMetadataContext<M> — TaskLocal-backed 的 ambient carrier。在 Usecase 入口用 withValue(_:operation:) 設一次，巢狀的 repository.save 透過 structured concurrency 自動繼承。
  • 型別化 metadata 通道 — EventStore 新增 associatedtype Metadata: EventMetadata；append 收型別化的 metadata: Metadata?。

✓ 不受影響

  • DomainEvent protocol — 仍有 associatedtype Metadata 與 var metadata。
  • AggregateRoot / Usecase / DomainEventBus / ReadModel — 介面未動。
  • EventSourcingProjector.apply(readModel:events:) — 簽章不變。
  • EventStore.fetchEvents — 仍回傳 (events:, latestRevision:) tuple。

為什麼做這次重構?

0.x 用 external: [String:String]? 字串字典把 audit metadata 帶到儲存層,造成三個問題:(1) Domain 抽象被基礎設施 metadata 汙染;(2) schema 被鎖死成 dict,無型別安全的擴充空間;(3) 跟既有的 DomainEvent.Metadata 機制重複。 1.0 用 ambient context + pluggable schema 一次解決——詳見 Migration Guide 的「為什麼要改」。

0.x initial line

1.0 之前的開發版本線。採 EventStorageCoordinator 為儲存抽象、 以 external: [String:String]? 字典作為 metadata 通道。後續所有提交與功能 請參考 GitHub 的 commit 歷史。
