Install安裝

Add the package to your Package.swift. DDDKit is the umbrella product; it re-exports the core protocols, the event sourcing layer, the KurrentDB adapter, the in-memory event bus and read model persistence.

在 Package.swift 加入套件。DDDKit 是 umbrella product，會一併重新導出核心協定、event sourcing 層、KurrentDB 轉接層、記憶體內 event bus 與 read model 持久化。

dependencies: [
    .package(url: "https://github.com/gradyzhuo/swift-ddd-kit.git", from: "1.3.0")
],
targets: [
    .target(
        name: "MyContext",
        dependencies: [
            .product(name: "DDDKit", package: "swift-ddd-kit"),
        ]
    )
]

Latest stable · 1.3.0最新穩定版 · 1.3.0

Cross-context events over Apache Pulsar跨 Bounded Context 的事件：Apache Pulsar

Domain events stay inside their context. What crosses the boundary is a Published Language event, and 1.3 adds both halves of that trip over Apache Pulsar, with neither side depending on a Pulsar client library.

Domain event 留在自己的 context 裡；跨越邊界的是 Published Language 事件。1.3 補上這段旅程在 Apache Pulsar 上的兩端， 而且兩端都不依賴 Pulsar 的 client library。

PublishedLanguage

The zero-dependency wire envelope, PublishedLanguageEvent, shared by producers and consumers.

零依賴的 wire envelope PublishedLanguageEvent，由發送端與接收端共用。

ContextForwarder

Produce side. Subscribes to the context's own KurrentDB, translates events through ForwardingRules and posts them to Pulsar's REST produce endpoint. Bearer-token auth and a self-healing ForwarderGroup.

發送端。訂閱自身 context 的 KurrentDB，透過 ForwardingRule 轉譯後 POST 到 Pulsar 的 REST produce 端點。支援 Bearer token 驗證與會自我修復的 ForwarderGroup。

ContextReceiver

Consume side, portable. Drives a PulsarMessageSource into your handler with permit-based flow control, settlement rules and a DeadLetterMonitor. Fully testable offline.

接收端，可攜。透過 permit 流量控制把 PulsarMessageSource 的訊息送進你的 handler，內含結算規則與 DeadLetterMonitor。可完全離線測試。

ContextReceiverWebSocket

The concrete transport over Pulsar's WebSocket consumer protocol. Linux-only for now: the upstream WebSocket dependency does not build on the macOS 26 SDK.

走 Pulsar WebSocket consumer 協定的實際 transport。目前僅支援 Linux：上游的 WebSocket 依賴在 macOS 26 SDK 上無法編譯。

Things only a live broker teaches. REST produce takes a raw JSON string while the WebSocket consumer returns it base64-encoded. Delivery is at-least-once, so derive downstream ids from the upstream eventId to stay idempotent. Set maxRedeliverCount and deadLetterTopic, or a message you gave up on will redeliver forever.

只有真實 broker 才會教你的事。 REST produce 收原始 JSON 字串，WebSocket consumer 卻回傳 base64 編碼。投遞是 at-least-once，請從上游 eventId 推導下游 id 以保持冪等。務必設定 maxRedeliverCount 與 deadLetterTopic，否則放棄的訊息會無限重送。

swift-kurrentdb's RecordedEvent and Streams cannot be constructed from outside that package, so a fake could never conform to the client protocol. 1.2 adds a narrow EventStoreClient seam covering exactly what the coordinator and the projection runners call, and ships two conformances: the live one, and one that needs no server at all.

swift-kurrentdb 的 RecordedEvent 與 Streams 無法在套件外建構，因此假物件永遠無法 conform 原本的 client 協定。 1.2 新增一個窄的 EventStoreClient seam，只涵蓋 coordinator 與 projection runner 實際呼叫的操作，並提供兩個實作：一個接真實伺服器，一個完全不需要伺服器。

InMemoryEventStoreClient

In the new KurrentSupportInMemory product. Real optimistic-concurrency semantics, $ce- category routing, replay-on-subscribe for "seed then subscribe" tests, and an opt-in deliveryDelay to test eventual consistency on purpose.

位於新的 KurrentSupportInMemory product。真實的 optimistic concurrency 語意、$ce- category 路由、訂閱時重播（方便「先塞資料再訂閱」的測試），以及可選的 deliveryDelay 用來刻意測試最終一致性。

包著真實 KurrentDBClient 的生產環境實作。client: KurrentDBClient 便利初始化器保留，既有呼叫端不需修改。

KurrentDBClient.withPooledIntegrationTestClient 在設定 KURRENTDB_POOL_URLS 時從連線池借用 client，否則退回固定叢集。純選用。

Why swift-ddd-kit為什麼選擇 swift-ddd-kit

The Swift server ecosystem has matured, but the building blocks of a production DDD architecture, aggregate roots, event-sourced repositories, CQRS projectors and event migration, have been missing. swift-ddd-kit fills that gap.

Swift 後端生態已經成熟，但 production 等級 DDD 架構的建構元件，aggregate root、event-sourced repository、CQRS projector、事件 migration，一直缺席。swift-ddd-kit 補上這一塊。

Events are the source of truth事件就是事實的來源

State is never stored directly. Every change is an immutable DomainEvent, and state is rebuilt by replaying them through when(happened:).

狀態從不直接儲存。每次變更都是一個不可變的 DomainEvent，狀態透過 when(happened:) 重播事件重建。

Aggregates guard invariantsAggregate 守住不變條件

Business rules live in AggregateRoot. apply(event:) mutates state, runs ensureInvariant() and queues uncommitted events. No anemic models mutated from outside.

商業規則放在 AggregateRoot。apply(event:) 變更狀態、執行 ensureInvariant() 並排入未提交事件。沒有從外部被改動的貧血模型。

Write and read stay apart讀寫分離

The write side appends events; EventSourcingProjector folds them into ReadModels on the read side. A persistent-subscription runner keeps projections live.

寫入端只附加事件；讀取端由 EventSourcingProjector 把事件折疊成 ReadModel。Persistent subscription runner 讓投影持續更新。

Swift 6 strict concurrencySwift 6 strict concurrency

Native async/await throughout. Ambient metadata rides on TaskLocal, so audit and tenant data never leak into domain types.

全面使用原生 async/await。Ambient metadata 搭在 TaskLocal 上，稽核與租戶資料永遠不會滲入 domain 型別。

Less boilerplate, checked at build time更少樣板，在建置期檢查

SPM build-tool plugins turn event.yaml, projection-model.yaml and variables.yaml into Swift. Mistakes surface as build failures, not runtime surprises.

SPM build-tool plugin 把 event.yaml、projection-model.yaml 與 variables.yaml 轉成 Swift。錯誤在建置時就浮現，而不是執行期才發現。

Testable without infrastructure不需基礎設施也能測

InMemoryEventStoreClient stands in for KurrentDB, ContextReceiver is fully offline-testable, and TestUtility covers the integration runs that do need a server.

InMemoryEventStoreClient 代替 KurrentDB，ContextReceiver 可完全離線測試，TestUtility 則涵蓋真的需要伺服器的整合測試。

How it works運作方式

The write side and the read side share no code path. Both talk to KurrentDB on their own: commands append events, queries read those same events to build query-optimised models.

寫入端與讀取端沒有共用的程式路徑，各自對 KurrentDB 存取：command 附加事件，query 讀取同一批事件建立查詢最佳化的模型。

  1. Define events定義事件

    Conform to DomainEvent, or generate them from event.yaml.

    讓事件 conform DomainEvent，或從 event.yaml 生成。

  2. Model the aggregate建立 aggregate

    Implement AggregateRoot; when(happened:) turns each event into state.

    實作 AggregateRoot；when(happened:) 把每個事件轉成狀態。

  3. Map stored records back把儲存的記錄映射回來

    An EventTypeMapper decodes KurrentDB records into typed events.

    EventTypeMapper 把 KurrentDB 的記錄解碼回型別化的事件。

  4. Save儲存

    repository.save(aggregateRoot:) appends the uncommitted events with optimistic concurrency.

    repository.save(aggregateRoot:) 以 optimistic concurrency 附加未提交的事件。

  5. Find讀取

    repository.find(byId:) replays the stream and rebuilds the aggregate.

    repository.find(byId:) 重播 stream、重建 aggregate。

  6. Project投影

    An EventSourcingProjector folds events into a ReadModel, on demand or through a persistent subscription.

    EventSourcingProjector 把事件折疊成 ReadModel，可即時計算，也可透過 persistent subscription 持續更新。

Quick Start快速上手

1. Events1. 事件

import DDDKit

struct OrderCreated: DomainEvent {
    var id: UUID = .init()
    var occurred: Date = .now
    var aggregateRootId: String
    let customerId: String
}

struct OrderCancelled: DeletedEvent {
    var id: UUID = .init()
    var occurred: Date = .now
    let aggregateRootId: String
}

2. Aggregate root2. Aggregate root

final class Order: AggregateRoot {
    typealias DeletedEventType = OrderCancelled

    let id: String
    private(set) var customerId: String = ""
    var metadata: AggregateRootMetadata = .init()

    init(id: String, customerId: String) throws {
        self.id = id
        try apply(event: OrderCreated(aggregateRootId: id, customerId: customerId))
    }

    required init?(events: [any DomainEvent]) throws {
        guard let first = events.first as? OrderCreated else { return nil }
        self.id = first.aggregateRootId
        try apply(events: events)
    }

    func when(happened event: some DomainEvent) throws {
        switch event {
        case let e as OrderCreated: customerId = e.customerId
        default: break
        }
    }
}

3. Mapper and repository3. Mapper 與 repository

struct OrderEventMapper: EventTypeMapper {
    func mapping(eventData: any RecordedEventLike) throws -> (any DomainEvent)? {
        switch eventData.eventType {
        case "OrderCreated":   return try eventData.decode(to: OrderCreated.self)
        case "OrderCancelled": return try eventData.decode(to: OrderCancelled.self)
        default:               return nil
        }
    }
}

final class OrderRepository: EventSourcingRepository {
    typealias AggregateRootType = Order
    typealias Store = KurrentStorageCoordinator<Order, CustomMetadata>

    let store: Store
    init(client: KurrentDBClient) {
        store = .init(client: client, eventMapper: OrderEventMapper())
    }
}

4. Save and find4. 儲存與讀取

let client = KurrentDBClient(settings: .localhost())
let repository = OrderRepository(client: client)

let order = try Order(id: "order-001", customerId: "customer-42")
try await repository.save(aggregateRoot: order)

let found = try await repository.find(byId: "order-001")   // replayed from the stream

try await repository.delete(byId: "order-001")   // soft delete: appends OrderCancelled
try await repository.purge(byId: "order-001")    // hard delete: removes the stream

5. Metadata without touching the domain5. 不碰 domain 的 metadata

struct AuditMetadata: EventMetadata {
    let operatorId: String
    let tenantId: String
}

// Bind the schema on the store …
typealias Store = KurrentStorageCoordinator<Order, AuditMetadata>

// … and set it once at the use case entry. save() picks it up automatically.
try await EventMetadataContext<AuditMetadata>.withValue(meta) {
    try await repository.save(aggregateRoot: order)
}
