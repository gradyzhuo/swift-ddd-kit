Framework Migration Guide

swift-ddd-kit  1.3 → 1.4

EventStore 契約、本機事件儲存與 iOS — 給「依賴 swift-ddd-kit 的下游專案」的升級指南，一併涵蓋 1.4 預覽版期間的變更

target: swift-ddd-kit Swift 6.1+ / Ubuntu / macOS 15+ / iOS 18+ ⚠ source-breaking + behaviour change audience: human + AI agent
version transition
FROM1.3
→
TO1.4

1.3.0 之後的下一個穩定版是 1.4.0。1.4 把每個 EventStore 該怎麼做寫成一份契約 （revision 從 0 起算、版本不符一律丟 DDDError.commitConflict、purge 改為永久的 tombstone）， 新增檔案式的 PersistentEventStore，並讓 DDDCore、EventSourcing、LocalEventStore 以 product 發佈、可建置於 iOS 18+。1.4 預覽版期間已發佈的 Postgres read model 強化、template variables 與 forwarder 變更也在本指南內。 AggregateRoot / DomainEvent / Usecase 的介面不變。

Source-breaking 變更

這些變更會讓既有程式碼編不過，編譯器會指出位置。

SB1  dependency  swift-kurrentdb ≥ 2.6.0

2.6.0 讓讀取已 tombstone 的 stream 回報 KurrentError.resourceDeleted，1.4 的 purge 語意依賴它。 swift-ddd-kit 1.3 要求 2.3.0；若你的 Package.swift 直接依賴 swift-kurrentdb，下限要一起提高。

- .package(url: "https://github.com/gradyzhuo/swift-kurrentdb.git", from: "2.3.0")
+ .package(url: "https://github.com/gradyzhuo/swift-kurrentdb.git", from: "2.6.0")

SB2  enum case  DDDError.Code 501–504 與 EventStoreClientError 新 case

型別新增 case來源
DDDError.CodecommitConflict（501）、streamPurged（502）、storeUnavailable（503）、storeCorrupted（504）1.4.0
EventStoreClientErrortombstoneUnsupported1.4.0
EventStoreClientErrorsubscriptionGroupNotFound(stream:group:)1.4.0-beta.12

沒有 default 的 exhaustive switch 需要補上這些 case。storeUnavailable 的原因以 error.storeUnavailableReason（DDDError.StoreUnavailableReason：invalidLocation、 streamNameTooLong、io、occupied、closed）讀取；目前只有 PersistentEventStore 丟 503／504。

SB3  codegen  Generator 產出檔的 import

產出檔現在 import Foundation、DDDCore、EventSourcing，不再 import KurrentSupport／KurrentDB。 若 event.yaml 以 KurrentSupport 限定型別（例如 KurrentSupport.CustomMetadata），或使用只有 KurrentSupport／KurrentDB 提供的非限定型別，重新生成後會編譯失敗；KurrentSupport 的 typealias 無法補救，因為該模組沒被 import。二選一：

做法一：改型別名稱（event.yaml）

- actorMetadata: KurrentSupport.CustomMetadata
+ actorMetadata: EventSourcing.CustomMetadata
  # 或非限定的 CustomMetadata

做法二：補依賴（event-generator-config.yaml）

accessModifier: public
dependencies:
  - KurrentSupport

SB4  signature  ForwardingRule.translate 回傳陣列（1.4.0-beta.9）

- ForwardingRule(eventTypes: ["X"]) { record in try makeEvent(record) }      // PublishedLanguageEvent?
+ ForwardingRule(eventTypes: ["X"]) { record in [try makeEvent(record)] }    // [PublishedLanguageEvent]

原本回 nil 的地方改回 []。一筆紀錄產生多個事件時，每個事件要有穩定且不重複的 eventId（見 ForwardingRule 的 doc comment）。

SB5  platform  iOS／Mac Catalyst 最低版本 18

Package.swift 的 platforms 加上 .iOS(.v18)，這個值套用到本 package 的每一個 product， 不只新的三個。以 iOS 或 Mac Catalyst 18 以下為目標建置任一 product 的專案會建置失敗，需把 deployment target 提高到 18。 只建置 macOS（仍是 15+）或 Linux 的專案不受影響。

SB6  toolchain  Swift 6.1+（1.4.0-beta.12）

swift-tools-version 從 6.0 提高到 6.1，Swift 6.0 工具鏈無法再建置本 package。

SB7  protocol  EventStoreClient 新 requirement（1.4.0-beta.12）

自訂的 EventStoreClient conformance（wrapper、decorator、自製 fake）必須實作 ensurePersistentSubscription(stream:group:settings:) 與 deletePersistentSubscription(stream:group:)，這兩個沒有預設實作。 1.4 另外新增的 tombstoneStream(name:) 有預設實作，編得過但執行時會失敗，見 BC2。

行為變更

編譯器不會指出這些 以下變更不影響編譯，但改變執行結果。升級後請逐條對照自己的程式碼與測試。

BC1  permanent  purge 改為 tombstone

  • KurrentStorageCoordinator.purge 呼叫 KurrentDB 的 tombstone(.any)：stream 永遠無法再寫入，之後對同一 id 的 append 丟 DDDError.streamPurged（502）。先 purge 再用同一個 id 重建 aggregate 的做法不再可行。
  • 對從未寫過的 id 呼叫 purge 也會成功，並讓該 id 永久保留。不要 purge 之後還會使用的 id。
  • EventSourcingRepository.purge 不再先 find：未知的 id 不再丟 aggregateNotFound，已 soft-delete 的 aggregate 也可以被 purge。
  • 資料不會被物理抹除：KurrentDB 保留到 scavenge；PersistentEventStore 則從 stream 檔中移除 payload。

BC2  runtime  wrapper 必須轉呼叫 tombstoneStream(name:)

EventStoreClient 新增 tombstoneStream(name:)。協定擴充提供標為 deprecated 的預設實作，所以舊的 conformance 編得過，只有一個 deprecation 警告；但 purge 在執行時丟 EventStoreClientError.tombstoneUnsupported，stream 也不會被 purge。

struct LoggingClient: EventStoreClient {
    let base: any EventStoreClient
    // ...其他 requirement...
    func tombstoneStream(name: String) async throws {
        try await base.tombstoneStream(name: name)
    }
}

BC3  error  版本衝突統一丟 DDDError.commitConflict

KurrentStorageCoordinator 與 InMemoryEventStore 在衝突時都丟 DDDError.commitConflict（501），取代 EventStoreClientError.wrongExpectedRevision、KurrentError.wrongExpectedVersion、InMemoryStorageCoordinatorError.versionConflict。

- } catch KurrentError.wrongExpectedVersion { ... }
+ } catch let error as DDDError where error.code == .commitConflict {
+     let conflict = error.commitConflict   // CommitConflict { id, expected, actual }
+     ...
+ }

BC4  contract  其他 store 行為

  • 空陣列的 append 直接回傳 nil，不寫入也不呼叫 client。
  • 對已存在的 stream 傳 version: nil 會衝突（nil 代表要求 stream 尚不存在）。
  • fetchEvents 依 stream 回傳的順序，不再依 occurred 排序。
  • EventSourcingRepository.save 在沒有新事件時不呼叫 store。
  • InMemoryStorageCoordinator 更名為 InMemoryEventStore（舊名保留為 deprecated typealias，最早 1.6 移除），revision 從 0 起算。斷言 revision 或衝突的測試要更新。
  • InMemoryEventStoreClient 現在模擬 tombstone 與事件 id 冪等重送，與真 server 一致。

BC5  error  超過 Int64.max 的預期 revision

KurrentDB 無法接受大於 Int64.max 的預期 revision，以前會得到 server 回的 gRPC 內部錯誤。現在 KurrentStorageCoordinator.append 在 version 大於 UInt64(Int64.max) 時不送出 append，改丟 DDDError.commitConflict，actual 為讀 stream 得到的尾端 revision（stream 不存在時為 nil）； 該 stream 已被 tombstone 時丟 streamPurged。Int64.max 本身照常送出。

BC6  default  Postgres snapshot 預設改為 monotonic（1.4.0-beta.12）

Postgres stores 與 PostgresReadModelMigration 預設 SnapshotWriteMode.monotonic：只接受嚴格較新的 revision， 寫入 read_model_snapshots_monotonic 表。原本使用預設表 read_model_snapshots 的專案二選一：以 KurrentProjection.rebuild 重建，或傳 writeMode: .overwrite 沿用舊表與舊行為。 migration、stores 與 PostgresReadModelSnapshots 要傳相同的 tableName／writeMode。

BC7  runner  Subscription runner 自行管理 group（1.4.0-beta.12）

  • 兩個 runner 的 subscriptionSetup: 預設 .ensure(...)：訂閱前建立 group；group 消失時重建並丟 subscriptionGroupNotFound，呼叫端要再呼叫 run()（例如帶 backoff 的重啟迴圈）。需要建立 persistent subscription 的權限；沒有權限時傳 .manual 維持舊行為。
  • TransactionalSubscriptionRunner 依註冊順序逐一 dispatch projector，不再併發。
  • 生成的 projector apply() 改用 default: continue，遇到未列出的事件不再中斷整個 fold。重新生成即可。

BC8  forwarder  ContextForwarder 重建遺失的 group（1.4.0-beta.11）

訂閱 group 在執行期間消失時，forwarder 以原本的設定重建 group 並丟出錯誤，讓外層在 backoff 後重新訂閱。新 group 從 subscriptionSettings.startFrom（預設 .end）開始讀，group 消失期間寫入的事件不會補送。

升級步驟清單

先處理會讓編譯失敗的項目，再逐條檢查行為變更。

  1. 工具鏈 — 使用 Swift 6.1 以上（SB6）。
  2. Bump 依賴 — swift-ddd-kit 改成 from: "1.4.0"；若直接依賴 swift-kurrentdb，下限改成 2.6.0（SB1）。
  3. iOS 目標 — iOS／Mac Catalyst 的 deployment target 提高到 18（SB5）。
  4. 重新生成 — 重建讓 plugin 重新產生程式碼；event.yaml 若以 KurrentSupport 限定型別，改型別或在 config 補 dependencies（SB3）。
  5. Forwarder rule — ForwardingRule 的 closure 改回傳陣列（SB4）。
  6. Exhaustive switch — 補上 DDDError.Code 501–504 與 EventStoreClientError 的新 case（SB2）。
  7. 自訂 EventStoreClient — 實作或轉呼叫 ensurePersistentSubscription、deletePersistentSubscription 與 tombstoneStream；確認沒有 tombstoneStream 的 deprecation 警告（SB7、BC2）。
  8. 衝突處理 — catch 舊衝突錯誤的地方改成 DDDError.commitConflict（BC3）。
  9. In-memory store — InMemoryStorageCoordinator 改成 InMemoryEventStore，更新斷言 revision 的測試（BC4）。
  10. Purge — 逐一檢查 purge 的呼叫：被 purge 的 id 永遠無法再寫入（BC1）。
  11. Postgres read model — 選定 writeMode：.monotonic 搭配 rebuild，或 .overwrite 沿用既有表（BC6）。
  12. Runner — 確認帳號能建立 persistent subscription，否則傳 subscriptionSetup: .manual；run() 丟 subscriptionGroupNotFound 後要重新啟動（BC7）。
  13. 編譯 + 測試 — swift build 解掉剩餘錯誤，跑測試套件確認行為。
